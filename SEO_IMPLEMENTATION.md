# SEO Implementation

Everything here comes from one data module (`src/seo/pages.ts`) feeding four
consumers, so the runtime page, the static HTML, the sitemap and the
structured data can never say different things about the same URL.

```
src/seo/pages.ts    (PAGE_SEO: title, description, image, breadcrumb, dates…)
        │
        ├── src/seo/head.ts    buildHead() → <title>/<meta>/<link>/JSON-LD tags
        │        ├── used at BUILD TIME by scripts/prerender.mjs (renderHeadHtml)
        │        └── used at RUNTIME by <Seo> (applyHead) on client-side navigation
        ├── src/seo/schema.ts  buildSchema() → the JSON-LD graph
        └── src/seo/files.ts   buildSitemap() / buildRobots()
```

## 1. Page-level metadata

Every route in `src/routes.ts` has a matching entry in `PAGE_SEO`
(`src/seo/pages.ts`) with: `title`, `description`, `name` (visible H1 used in
breadcrumbs), `image` + `imageAlt`, `indexable`, `lastModified`,
`changeFrequency`, `priority`, and `breadcrumb` (the trail below Home).

`scripts/prerender.mjs` has a drift guard: if a route has no `PAGE_SEO` entry,
no `PAGE_MODULES` entry, or its module isn't in Vite's build manifest, the
build fails with a clear message instead of silently shipping a blank page —
the same discipline Whiteline's `gen-routes.ts` used (see
[WHITELINE_PROJECT_ANALYSIS.md](WHITELINE_PROJECT_ANALYSIS.md)).

`buildHead()` (`src/seo/head.ts`) turns one `PAGE_SEO` entry into:

- `<title>`
- `<meta name="description">`
- `<meta name="robots">` — `index, follow, max-image-preview:large,
  max-snippet:-1` when indexable, `noindex, follow` otherwise (the 404 page,
  or every page when `VITE_ALLOW_INDEXING=false`)
- Open Graph: `og:type`, `og:site_name`, `og:locale` (`en_IN`), `og:title`,
  `og:description`, `og:image` (+ width/height/alt), and `og:url` (omitted on
  the 404 page, which has no canonical identity)
- Twitter Card: `summary_large_image` + title/description/image/alt
- `<link rel="canonical">` (omitted on the 404 page)
- one `<script type="application/ld+json">` (see §3)

The exact same tag list is used by `renderHeadHtml()` at build time (string
HTML, escaped, injected into the prerendered page) and by `applyHead()` at
runtime (DOM mutation, called from `<Seo page="…">` whenever the route
changes) — see `PROJECT_ARCHITECTURE.md §3`.

## 3. Structured data (JSON-LD)

`src/seo/schema.ts` builds one `@graph` per page from facts stated elsewhere
in the design or in `data/site.ts` — nothing fabricated (no rating, no
founding date, no price range, unlike the Whiteline reference, which the
design doesn't give Ladder7):

| Node | On | Built from |
| --- | --- | --- |
| `Organization` | every page | `data/site.ts`: name, email, phone, both office addresses, social links, logo |
| `WebSite` | every page | division name/tagline, `publisher` → the Organization |
| `WebPage` / `AboutPage` / `ContactPage` | every page | the page's own title/description/canonical URL |
| `BreadcrumbList` | every page except Home | `PAGE_SEO[...].breadcrumb` |
| `Service` (one per capability) | `/services` only | `data/services.ts`: `CAPABILITIES` + `SOLUTIONS` |
| `FAQPage` | Home, Services, Contact | `data/company.ts`: `FAQS` — **only** on pages that actually render `<FaqSection>`, so the markup always matches visible content (the same rule Whiteline's `aggregateRating` split followed) |

Validate after any content change: Google's [Rich Results
Test](https://search.google.com/test/rich-results) or
`https://validator.schema.org/`, against a built page (see §6).

## 4. Technical SEO files

Both generated by `scripts/prerender.mjs` from the exact same route table —
there is no second list to keep in sync:

- **`robots.txt`** (`buildRobots()`): `Allow: /` + a `Sitemap:` line, or
  (when `VITE_ALLOW_INDEXING=false`) `Disallow: /` for every path — used on
  staging so a preview deploy can never be indexed.
- **`sitemap.xml`** (`buildSitemap()`): one `<url>` per `indexable` route,
  with `lastmod`/`changefreq`/`priority` from `PAGE_SEO`.
- **`404.html`**: a real, separate file the server returns with HTTP 404 (see
  `server.mjs`) — never the home page's markup under a 404 status (a
  "soft 404" search engines penalise).
- **Favicon / app icons / manifest**: `public/icons/*` (generated by
  `scripts/generate-icons.mjs` from the brand logo's own emblem) and
  `public/manifest.webmanifest`.

## 5. Crawlability and rendering

- **No client-side-only rendering.** Every route is fully rendered HTML
  before any JavaScript runs (`react-dom/static` at build time — see
  `PROJECT_ARCHITECTURE.md §3`), then hydrated. A crawler that never executes
  JavaScript still sees the complete `<h1>`, body copy, links and JSON-LD.
- **Heading hierarchy**: exactly one `<h1>` per page (`PageHero`/`Hero`/the
  contact heading), `<h2>` for section titles, `<h3>` for cards/items within
  a section — checked with Lighthouse's `heading-order` audit (see
  [PERFORMANCE_REPORT.md](PERFORMANCE_REPORT.md)).
- **Internal linking**: every page links to every other page via the header,
  footer and overlay menu (`data/navigation.ts`); capability rows and service
  details cross-link between Home and Services.
- **Image alt text**: every `<ResponsiveImage>` call requires an `alt` prop
  (TypeScript enforces it); decorative images pass `alt=""` explicitly, never
  omit it. Photographic alt text describes what's shown, not a keyword list
  (e.g. the statue images' alt text, carried over verbatim from the design).
- **Clean URLs**: `/about`, `/services`, `/contact` — no trailing slashes
  (the server 301s `/about/` → `/about`), no query-string routing, no
  file extensions.
- **Canonical URLs**: absolute, from `VITE_SITE_URL`; never relative, never
  pointing at a different page than the one being served.

## 6. Verifying after a change

```bash
npm run build
node server.mjs            # http://localhost:8080
```

Then, on the running build:

- View source (not DevTools' rendered DOM) on each page: title, meta
  description, canonical, Open Graph tags and the JSON-LD `<script>` must
  all be present without running any JavaScript.
- `curl -s http://localhost:8080/robots.txt` and `/sitemap.xml`.
- `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/no-such-page`
  → must print `404`.
- Lighthouse SEO category (see
  [PERFORMANCE_REPORT.md](PERFORMANCE_REPORT.md)) — 100 on every page as of
  this release.
- Paste a built page's `<script type="application/ld+json">` contents into
  the Rich Results Test.

## 7. Changing SEO copy

Edit `src/seo/pages.ts` only. Keep titles under ~70 characters and
descriptions under ~160–170 (enforced by `src/seo/pages.test.ts`, which also
checks every route has an entry and the 404 page stays `indexable: false`).
Run `npm test` after editing.
